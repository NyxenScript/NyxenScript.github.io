# File structure

```text
nyx_lib/
  fxmanifest.lua        Resource description (name, version 0.4.0, files to load)
  config.lua            Default theme settings (NyxConfig)
  init.lua              Creates the global `nyx` in other scripts
  README.md             Short overview
  INSTALL.md            Installation guide
  client/
    main.lua            Core: opens/closes windows, theme, NUI messages, admin panel, core exports
    components.lua      Ready-made functions: alertDialog, inputDialog, ... and the nyx_demo command
    exports.lua         One export per shadcn component, plus emit and bind
    component_list.lua  List of component names (generated, do not edit)
  server/
    main.lua            Saves/sends the theme, commands, permission check, notify, server exports
  web/                  The web interface (needs building)
    package.json        Web dependencies and scripts
    theme-codes.json    YOU edit: shadcn code for every theme value
    theme-options.json  Generated: values the panel and server accept
    components.json     shadcn settings (style, icons, menu)
    index.html          Entry page
    vite.config.ts      Build settings
    tsconfig.json       TypeScript settings
    scripts/
      gen-exports.mjs       Used by `npm run exports` and `npm run build`
      snapshot-themes.mjs   Used by `npm run themes`
      set-style.mjs         Used by `npm run style`
      snapshot-presets.mjs  Old (version 0.2.0), no longer used
    src/
      main.tsx          Starts the web app
      App.tsx           Turns trees from Lua into real components, shows toasts
      index.css         Tailwind, font imports and the default theme variables
      presets/          CSS for each theme value (generated by `npm run themes`)
        index.css base.css theme.css chart.css radius.css fonts.css
      nyx/
        bridge.ts       Sends messages from the web page back to Lua
        classes.ts      Tailwind classes used from Lua
        registry.ts     Finds all shadcn components automatically
        theme.ts        Applies the theme options and dark mode
        runtime.css     Makes Font and Heading switchable while the game runs
      components/ui/    shadcn components (created by `shadcn add --all`)
      hooks/ lib/       Helpers added by shadcn (utils, highlighter, use-mobile ...)
    .themes-cache/      Finished codes of `npm run themes` (safe to delete)
    dist/               Built result (created by `npm run build`)
```

## What the server really needs

- `web/dist/`
- `web/theme-options.json`
- the Lua files: `fxmanifest.lua`, `config.lua`, `init.lua`, `client/` (with `component_list.lua`) and `server/`

Not `web/node_modules`, not `web/src`, and not `.themes-cache`.

## What `fxmanifest.lua` loads

| Part | Files |
|---|---|
| NUI page | `web/dist/index.html` |
| Files sent to players | `web/dist/**`, `init.lua` (so other resources can use `@nyx_lib/init.lua`) |
| Shared (client and server) | `config.lua` |
| Client | `init.lua`, `client/component_list.lua`, `client/main.lua`, `client/components.lua`, `client/exports.lua` |
| Server | `server/main.lua` (also reads `web/theme-options.json`) |

The order of the client files matters: the component list must load before `exports.lua`, which uses it.

## Saved data

The chosen theme is stored on the server in FiveM's KVP storage under the key `nyx_lib:theme3`. It is not a file in the resource folder, so reinstalling the resource does not delete it. Use `nyx_theme reset` to clear it.
